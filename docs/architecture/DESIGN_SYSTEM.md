# Shared design and configuration

`src/design-system/tokens.css` owns the spacing unit, typography scale, colors, radii, shadows, blur, breakpoints, container sizes, motion, and named application dimensions. Tailwind v4 reads these through `@theme`: `p-6` means six spacing units; `text-caption`, `h-editor-height`, `rounded-device`, and `min-h-touch-target` replace scattered arbitrary values. Change the token definition to update its consumers. `tokens.ts` exposes CSS references for JavaScript styles, without maintaining a second numeric scale. `component-styles.ts` owns shared typography, button, table, badge, input, choice, and dialog recipes. `lib/utils/classes.ts` merges these classes with knowledge of custom typography utilities, preserving font sizes alongside colors and letting intake palette classes replace administrative defaults.

`Text`, `Button`, and the table primitives own their appearance and reject `className` and `style` props. Put margins, placement, and responsive visibility in surrounding layout containers. Native spans remain for layout, decorative elements, and screen-reader-only content.

- `Text` separates semantics (`as="h1"`, `as="h2"`, `as="p"`, `as="span"`) from appearance (`variant="title"`, `"section"`, `"heading"`, `"body"`, `"small"`, `"caption"`, or `"micro"`). Use named tones, weight, alignment, wrapping, and monospace options. `variant="inherit"` keeps text inside buttons, badges, and alerts inheriting the enclosing primitive's styling. Patient text uses `intake`, `intakeSecondary`, or `intakeError` tones.
- `Button` takes `variant` (`primary`, `secondary`, `ghost`, `link`, `menu`, `segment`), `tone` (`primary`, `neutral`, `success`, `warning`, `danger`), `size` (`xs`, `sm`, `md`, `lg`, `icon`, `icon-sm`), and `fullWidth`. `md` and `lg` use the touch-target token. `theme="intake"` binds patient buttons to scoped palette aliases. Segmented controls use `selected`, which also sets `aria-pressed`. Loading disables the button and exposes `aria-busy`; native handlers and refs remain supported.
- `Th` and `Td` accept named `variant` (`default`, `title`, `meta`, `actions`), `padding`, `align`, `truncate`, and `desktopOnly`. Desktop form columns and inline row actions appear together at `lg`; smaller screens use the compact summary and action menu. `Tr` distinguishes header/body rows and accepts `interactive` and `selected`. Put cell typography in `Text` rather than styling the cell.

Patient theme palettes remain in `features/themes/domain/presets.ts`. Their scoped CSS variables are mapped with `@theme inline`, so `bg-intake-surface` resolves inside the current light/dark preview rather than against a global theme. Published palette snapshots remain independent of the editor's visual foundations.

`src/lib/constants/messages.ts` owns application copy, error/validation messages, and formatted text. `application.ts` owns shared routes, API endpoints, timing, authentication settings, and question defaults. HTML attributes, schema discriminants, database identifiers, and protocol keys remain at their typed boundaries; they are contracts rather than editable display copy.

`config/constants.mjs` defines logical environment keys, external variable names, values, and defaults. Consumers use `readEnvironment(ENVIRONMENT_KEYS.NODE_ENV)` and compare against `ENVIRONMENT_VALUES.PRODUCTION`; test overrides and tooling declarations use `ENVIRONMENT_NAMES[ENVIRONMENT_KEYS.NODE_ENV]`. `config/environment.mjs` is the environment access boundary for Next.js and Node tooling. Its getters read lazily. Server application modules use `src/lib/config/environment.ts`, which imports `server-only`; scripts and tooling import the MJS utility. The public Supabase getter keeps literal `NEXT_PUBLIC_*` references required by Next.js build-time replacement and returns only the public URL/key. Private reads reject browser execution. ESLint prevents direct environment access in source/scripts/tooling, while tests can override variables explicitly. Deployment providers and CI still declare their external environment variables normally; changing those external names also requires updating their deployment configuration.

Verification covers environment fallback/overrides, public key precedence, browser rejection of private reads, existing domain behavior, compilation, and generated styling. Database tests require a disposable database and were not part of this refactor's validation.
